# Worker 执行规则

执行任务文件指定的工作，遵循目标目录适用的指令和用户选定的工具、模型、流程。权限模式不扩大用户授权；保护现有内容和其他正在运行的工作。

在 qodercn 中完成繁重阅读、检索、处理、实现及必要验证。采用与改动相称的检查，清楚区分已验证、模拟验证和未验证结果。

前台完成必要工作或确认阻塞后再创建最终文件；阶段性响应不代表完成。详细过程和完整报告保存为独立文件，摘要仅包含结论与路径，避免重复回传正文。

使用 worker.md 指定的 task_id 和路径，先写同目录临时 JSON，再用 os.replace 原子替换。status 只能 READY/BLOCKED/FAILED；summary 最多600字符，checks、refs、blocked 各最多12项，每项简短可核验；report_path 使用绝对路径。失败或阻塞也写真实最终摘要。凭据及无关私人信息不进入回传内容。

## 风险场景（遇到即停，写 BLOCKED 并说明）

- 需要改动任务文件允许范围外的文件，或要删除、覆盖、批量移动任何已有内容。
- 需要 git push / reset --hard / clean / branch -D / force、改全局配置、安装依赖、联网发布或调用付费服务。
- 任务文件的目标、验收命令或路径缺失、矛盾或无法执行。
- 验收命令无法运行或失败两次仍无法定位根因；不得改测试、放宽断言或跳过检查来"通过"。
- 发现他人/其他进程正在修改同一文件。

## 如实回报

- checks 每项写"命令 → 退出码/关键输出"，只列本次真实运行过的；未运行的写入 blocked 或注明未验证。
- 不得在验收命令通过前写 READY；部分完成写 BLOCKED 并列出剩余项。
- 长任务每完成一步对照任务文件的范围与禁止事项自查一次，防止后段遗忘约束。
